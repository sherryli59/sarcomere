## Executive summary

**Reason 3 was redefined, and that fixed the Z-disc.** The Sep-29 handoff
established that `am_overlap_occlusion` was a proximity-coverage proxy firing in
vacuum. It is now a penetration test: `decide_barbed_tip_capsule_penetration`
deletes an ACTN2 link only when a linked actin's barbed tip has entered the
myosin capture capsule by at least `aa_occlusion_rupture_penetration`. This is
the rule the design called for — repel on approach, delete only on actual entry.

**The legend was not updated, and this is a live trap.**
`meta@aa_local_link_detachment_reason_codes` still describes code 3 as the old
coverage rule. **Code 3 therefore means two different things depending on which
binary wrote the file.** Any cross-campaign comparison of reason-3 counts across
the 2026-09-29 boundary is invalid unless the binary is identified first.

**The capsule tiles the box at production density, which is why the old rule was
catastrophic there and merely bad in the minimal rig.** At production filament
count the capture capsules overlap: capsule volume fraction 1.18 versus 0.04 in
the minimal rig, and nearest-neighbour transverse spacing 0.061 um against a
0.260 um capsule diameter. Reducing the capture radius to R = 0.080 um at
production scale took reason-3 events from 15618 to 450.

**The AM interface is loose because every run switches off all three angular AM
terms, not because the physics is missing.** See Correction 2 — this is a
run-configuration null of the same kind as `k_mm = 0` for myomesin.

**Strong-head occupancy is at its kinetic ceiling, exactly.** MEASURED 19.3-20.6%
strong against a closed-form prediction of 20.00% from the model's own rates. It
is not SRX (4.7-5.6% off_srx), not calcium (thin activation measured 1.000, fully
saturated), and not overlap. Raising it requires changing a rate or the head
count, and `am_k_strong_off` is the only unbounded knob.

**`k_soff = 27` works in the minimal rig and FAILS at production.** A confirmed
negative; see In flight.

## Code changes (uncommitted)

### 1. Reason 3 redefined — `decide_barbed_tip_capsule_penetration`

```
- decide_am_overlap_occlusion(crosslinkable_ratio_i, crosslinkable_ratio_j, epsilon = 1e-12)
+ decide_barbed_tip_capsule_penetration(penetration_i, penetration_j, rupture_penetration)
```

The call site (`sarcomere_actn2.cpp:1654`) now reads
`actin["aa_barbed_tip_penetration"]` for both linked actins and compares against
`aa_occlusion_rupture_penetration`. This removes the dependence on
`crosslinkable_ratio`, and with it the overloaded zero of
`subsegment_within_distance` that produced Sep-29 correction 2.

**The legend string in `sarcomere_io.cpp` was NOT updated.** Fix this before
committing, or every future reader inherits the trap above.

### 2. `compute_barbed_tip_myosin_endstop` (`interaction.cpp:1182`)

A purely axial end-stop at the capsule's hemispherical cap:

```
cap_extension        = sqrt(max(0, R^2 - transverse_distance^2))
capsule_axial_bound  = 0.5*myosin.length + cap_extension
signed_clearance     = |axial_coordinate| - capsule_axial_bound
compression          = onset - signed_clearance
force                = force_max * tanh(stiffness*compression/force_max)
outward              = end_sign * axis          // AXIAL only, not the capsule normal
force_on_myosin      = -force_on_actin           // momentum conserving
```

Deliberately axial rather than along the capsule normal: the radial sterics
already hold the transverse separation, and a normal-directed force at the cap
would fight them. Force-capped with `tanh`, so it inherits the usual caveat that
`F_max` is set by the displacement cap, not by physics.

### 3. `aa_overlap_occlusion_veto` (bool, default true) — unchanged from Sep-29

Still present and still the switch that disables reason 3 entirely. With reason 3
redefined, `=false` is now a much weaker intervention than it was.

### Strong-head occupancy is at the kinetic ceiling

The duty cycle is a four-state loop: detached -> weak -> strong -> detached, with
an off-pathway OFF/SRX state. Closed form:

```
f_strong = B/(A+B),  A = T_d + T_w,  B = P*T_s
T_d = 1/k_on,  T_w = 1/(k_ps + k_woff),  T_s = 1/k_soff,  P = k_ps/(k_ps + k_woff)
```

Rates, verified from `main.cpp` defaults and confirmed identical in both the
production and minimal sbatch: `am_k_on = 100`, `am_k_weak_off = 200`,
`am_k_powerstroke = 200`, `am_k_strong_off = 160`, `am_thick_recruit_rate = 15`.

**PROJECTED** (closed form above, no noise term — these are exact algebra):

| knob driven to its limit | limiting f_strong |
|---|---:|
| baseline, all rates as shipped | 0.2000 |
| `k_on` -> infinity | 0.5556 |
| `k_ps` -> infinity | 0.3846 |
| `k_woff` -> 0 | 0.2941 |
| `k_soff` -> 0 | 1.0000 |

**MEASURED** (separate table on purpose — do not read these as rows of the one
above), from `head_budget.py` over the production trajectories:

| quantity | value | noise scale |
|---|---:|---|
| strong-head fraction | 19.3-20.6% | range over 8 runs |
| off_srx fraction | 4.7-5.6% | range over 8 runs |
| thin-filament activation `am_thin_activation` | 1.000 | saturated, no variation |

The measured 19.3-20.6% sits on the projected 20.00%. **`k_soff` is the only
knob with no ceiling below 1**, which is why the ladder went there.

### `k_soff` ladder — minimal rig

MEASURED, `ladder_result.py` / `ladder_struct.py`: f_strong rises with
decreasing `k_soff`, peaks near **k_soff = 27 at roughly 53%**, and **reverses
below that, degrading again by k_soff = 18**.

The closed form PROJECTS 59.7% at k_soff = 27 and 69.0% at k_soff = 18. The
measured ceiling is lower and non-monotonic, so the algebra is an upper bound
only: it ignores the load-dependent (catch-bond) strong-off term and competition
between heads for the same actin. **Do not use the closed form to set a target.**

### More links but less order — a pinning/annealing effect, not a contradiction

MEASURED, `kappa_course.py` / `anneal.py` / `anneal2.py`. Two different things
were being conflated:

- **Links front-load.** At t = 5 ms the link count is 2.42x higher in the arm
  with more links while nematic order S is *identical*. The order deficit then
  accrues over time, 0 -> -0.038, and annealing is ~4x slower. Early links pin
  the configuration before it can anneal.
- **kappa_aa does the reverse.** Order separates at t = 20 ms with link counts
  equal. So kappa_aa acts on orientation directly, not through link count.

These are opposite causal directions and must not be pooled.

## Corrections to earlier conclusions

1. **"`am_spokes_per_crown` will add heads."** WRONG, and the user caught it by
   asking why it would help with azimuth off. `heads.assign(am_heads_per_half,
   AMHeadState{})` at `sarcomere.cpp:2957` sizes the pool **before** `spokes` is
   read at `:2961`. `am_spokes_per_crown` only redistributes a fixed pool among
   axial stations. It cannot change the head budget.

2. **"No angular AM term exists; that is why the interface is loose."** WRONG as
   stated, and it was reported. **Three** angular/attractive AM mechanisms exist
   and are live in the force path:
   - `am_alignment_k`, applied at `sarcomere.cpp:4381` as
     `interaction_ramp * am_alignment_k * angular_occupancy`, **default 30.0**
     (`sarcomere.h:798`, `main.cpp:399`);
   - `kappa_am`, a nematic angle energy `0.5*kappa_am*(1 - dot^2)`
     (`interaction.cpp:38`), differentiated by autodiff at `:391` and `:403`;
   - `k_am`, the AM distance term in the same energy functions.

   Every production and minimal sbatch passes **`--am_alignment_k=0
   --kappa_am=0 --k_am=0`**. So the interface is loose by run configuration, not
   by missing code. This is the same pattern as myomesin: live, wired, never
   enabled. The correct statement is "all three AM angular terms are switched
   off in every run". Note this is **not** untested history — see Open questions
   for the 2026-08-03 result at `am_alignment_k = 120`.

3. **"`am_heads_per_half` is 9."** INCOMPLETE. The option **defaults to 141**
   (`main.cpp:381`, documented as ~14.3 nm crown spacing). Every current sbatch
   explicitly passes `--am_heads_per_half=9`. So the sparse-head regime is a
   deliberate run choice, and the untested lever is to stop overriding the
   default, not to add a feature.

4. **`compute_barbed_tip_myosin_endstop` is at `interaction.cpp:1182`, not
   `:1677`.** My working notes carried `:1677`, which is the *old*
   `compute_actin_myosin_repulsion` from the Sep-29 handoff. Three other
   references in my notes were off by one to three lines. All are corrected in
   the symbol table above; re-audit rather than trusting a prior handoff's
   numbers after a patch.

### Why more strong heads do NOT align (MEASURED 2026-10-05, job `46601602`)

A strong head is a **pin, not a lever**. Aligning an actin needs a couple: two
grips separated ALONG the filament. With `am_head_azimuth=false` the 3 spokes of
a crown sit at an IDENTICAL 3-D anchor, so only a MULTI-CROWN grip can make one.
`analysis/grip.py` counts distinct crowns per strong-head pair and conditions
theta_AM on it:

| | k_soff=160 | k_soff=27 |
|---|---:|---:|
| pairs with 1 distinct crown | **92.80%** | **87.02%** |
| 2 crowns | 6.77% | 11.55% |
| 3 crowns | 0.43% | 1.40% |
| theta_AM median, 1 crown | 32.35 | 42.30 |
| theta_AM median, 2 crowns | **17.22** | **21.83** |
| theta_AM median, 3 crowns | **8.63** | **10.58** |
| multi-crown axial span, min | **0.2250 um** | **0.2250 um** |
| multi-crown axial span, mean | 0.2887 um | 0.2837 um |

**Crown count predicts alignment powerfully** — median 32 deg at one crown
against 8.6 deg at three, a 4x spread. And the minimum span is **exactly
0.2250 um = one crown spacing**, confirming there is no intermediate: span is
either 0 (single crown, no couple) or >= 225 nm.

**But the correlation is mostly SELECTION, not causation, and the geometry
forces that reading.** Crown spacing is 225 nm while the reach budget is 80 nm,
so a misaligned actin physically CANNOT be touched by two crowns. Aligned
actins are the only ones eligible for a multi-crown grip. This measurement
cannot separate the two directions and should not be quoted as "multi-crown
grips align the actin".

**Roughly half of multi-head pairs are redundant.** Pairs with >=2 heads but
only ONE crown — identical anchor, zero span, zero couple — are 6.72% of all
pairs at k_soff=160 (**48.2% of multi-head pairs**) and 18.71% at k_soff=27
(**59.0%**). More duty makes the redundant share WORSE.

**Standardization proves the harm is within-stratum, not a mix effect.**
Splitting the 160 -> 27 change in stratified median theta_AM:

| term | effect |
|---|---:|
| k_soff=160 as measured | 31.22 deg |
| 27's crown mix with 160's within-stratum medians | 30.26 deg (**mix -0.96**) |
| k_soff=27 as measured | 39.48 deg (**within-strata +9.22**) |

So the extra duty DID shift the mix favourably (multi-crown 7.21% -> 12.98%,
worth -1 deg) and then degraded **every single stratum** by ~9 deg, swamping it.
That is not dilution; it is active interference — each long-lived pin resists
the ACTN2-driven rotation that is the only real aligner (`actn2_align`
+0.109..+0.136 pN um vs `am_head` +0.002..+0.010 and anti-aligning in slope;
`am_align`/`am_legacy`/`cb_bias` exactly 0.000).

**What would make "more heads -> more alignment" true:** get crown spacing under
the reach budget. hph=27 gives 75 nm < 80 nm and takes measured available span
from 0.4-0.7 nm to 89-91 nm, so a couple becomes available on a MISaligned
actin. See Open questions.

All three sd values are 21.9-22.7, so the arms differ in LOCATION, not spread.
Note the earlier "AM angle 30.2 vs 39.0" figures are MEDIANS (measured 30.9 vs
38.4), not means; say which when quoting.

**Interpret these against their own noise floors, which depend on N.**
`band_order` is a mean of unit phasors, so for RANDOM positions it scales like
1/sqrt(N). Monte Carlo, 20000 trials (`bandfloor.py`): N=2 -> mean **0.941**;
N=4 -> 0.696; N=320 -> 0.078 (p99 0.136); N=1600 -> 0.035 (p99 0.061). So
production's M order 0.392 over 320 myosins is ~5x its floor and far above p99,
and Z order 0.544 over 1600 tips is ~15x its floor — both strongly significant.
The frame-0 readings (M 0.055, Z 0.028) sit right at the floor, as a
near-random initial condition should. **The minimal-rig viewers report M order
0.862-0.943 with nM=2, which is at or BELOW the random floor of 0.941 — that
number is pure noise and must never be quoted or compared against production.**

**The two order parameters move in OPPOSITE directions**: myosin banding
improves 48% while actin-tip banding degrades 23%. That is a new observation and
it sharpens the pinning account — long-lived heads do organise the thick
filaments, by locking actin to myosin, but the ACTN2 network that sets Z-disc
banding is starved at the same time. Note M order and Z order are POSITIONAL
